# Расчёт асимптотики

`n` — длина входного массива; `r` — число найденных индексов; `p`, `q` — количества
положительных и отрицательных элементов. Ниже указана сложность методов `solve`.
Исходный массив не включается в дополнительную память, а возвращаемые массивы включаются.
Операции над `int` и `long` считаются константными, так как это типы фиксированной длины.

## Задача 12 подробнее

1. Создание массива записей `(значение, исходный индекс)` занимает `O(n)` времени и памяти.
2. `Arrays.sort` для объектов с компаратором сортирует записи за `O(n log n)` в худшем случае.
   Дополнительная память сортировки — `O(n)`.
3. Для каждого `i` выполняется двоичный поиск. На каждом шаге диапазон сокращается
   примерно вдвое, поэтому один поиск занимает `O(log n)` времени и `O(1)` памяти.
4. До `n` поисков дают `O(n log n)`. Итог:
   `O(n) + O(n log n) + O(n log n) = O(n log n)`.

Вложенность «проход + двоичный поиск» не означает `O(n²)`:
внутренний алгоритм делает логарифмическое, а не линейное число шагов.
Сортировка используется из стандартной библиотеки Java; в задаче 12 ручная
реализация сортировки не требуется. Сторонних библиотек структур данных нет.

## Полная программа с вводом и выводом

Для всех задач хранится входной `int[n]`, поэтому память всей программы — `O(n)`.
Чтение массива занимает `O(n)` времени. Строка вывода для задач 4, 8, 36, 37, 38 и 41 может занимать
`O(n)` символов при фиксированной разрядности чисел. Это не меняет итоговые оценки.
Для задач 2, 9 и 10 возможен ранний выход из `solve`, но чтение всего массива
по-прежнему требует `O(n)`.

## Разрядность арифметики

При `n < 100000` модуль суммы не превышает `99999 × 2147483648 < 2.15 × 10¹⁴`.
Это намного меньше максимума `long` — приблизительно `9.22 × 10¹⁸`.
Поэтому `long` достаточно для задач 5, 6, 11, 25 и каждой накопленной суммы в задаче 36.

В задаче 11 расстояние сравнивается как `|a[i] × n − sum|`.
Даже грубая оценка его модуля меньше `4.30 × 10¹⁴`, поэтому вычисления точны в `long`.
Приведение к `long` выполняется **до** умножения. Деление с округлением и `double`
для сравнения расстояний не нужны.

В задаче 26 каждый остаток лежит в диапазоне [0, M − 1], где M = 1000000007.
Промежуточное произведение не больше (M − 1)² = 1000000012000000036,
что меньше Long.MAX_VALUE = 9223372036854775807. Полное произведение не хранится.

## Сдвиг и удаление

В строке задачи 38 k означает нормализованный сдвиг, 0 ≤ k < n.
Суммарно выполняется не больше n обменов. Три последовательных вызова разворота
используют один и тот же массив, а каждый вызов хранит только индексы и одну переменную
для обмена. Поэтому дополнительная память O(1), несмотря на три прохода.

В задаче 41 пусть r — количество элементов, не равных x. Массив результата занимает
O(r) памяти, в худшем случае O(n). Два прохода дают O(n + n) = O(n) времени.

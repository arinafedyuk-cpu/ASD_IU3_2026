# Отчёт по лабораторной работе №1

**Тема:** линейный поиск и фильтрация массивов.  
**Выбранные задачи:** 1–12, по 1 баллу; всего 12 баллов по условию.  
**Стек:** Java 21, Maven, JUnit 5, Spotless, Checkstyle, JaCoCo.

## Идеи решений

1. **Минимум и максимум.** Начальные значения берутся из первого элемента.
   При просмотре каждого следующего элемента обновляются границы. Такой подход
   работает и для полностью отрицательного массива.
2. **Первое вхождение.** Проверяем элементы слева направо и сразу возвращаем индекс
   первого совпадения. Если проход закончился, возвращаем `-1`.
3. **Количество вхождений.** Просматриваем весь массив и считаем совпадения с `x`.
4. **Все индексы.** В буфер записываются индексы совпадений. Проход слева направо
   сразу обеспечивает возрастающий порядок. В конце копируется заполненная часть.
5. **Сумма на чётных индексах.** Проходим индексы с шагом 2, начиная с нуля.
   Накапливаем сумму в `long`.
6. **Элементы выше среднего.** Сначала вычисляем сумму в `long` и целое среднее,
   затем вторым проходом считаем строго большие значения. Целочисленное деление
   здесь точное по гарантии условия.
7. **Второй максимум.** Сохраняем два наибольших значения просмотренной части.
   Если встретился новый максимум, прежний максимум становится вторым.
   Иначе обновляем только второй максимум, если новый элемент больше него.
8. **Фильтрация по знаку.** Используем два буфера: для положительных и отрицательных.
   Добавляем элементы последовательно, поэтому порядок сохраняется. Нули пропускаем.
9. **Неубывание.** Сравниваем каждую соседнюю пару. Одного нарушения достаточно
   для `NO`; если нарушений нет, результат `YES`. Равенство допустимо.
10. **Последний кратный.** Движемся справа налево. Первый найденный кратный элемент
    имеет максимальный индекс. Ноль кратен любому ненулевому `k`.
11. **Ближайший к среднему.** После вычисления суммы сравниваем точные расстояния
    `|a[i] × n − sum|`. Умножение всех расстояний на положительное `n` сохраняет
    их порядок. Обновление только при строгом улучшении сохраняет первый индекс
    при равенстве расстояний. Возвращается значение элемента.
12. **Пара с суммой.** Создаём записи `(значение, исходный индекс)` и сортируем их
    сначала по значению, затем по индексу. Перебираем первый индекс `i` по возрастанию.
    Для него двоичным поиском находим первую запись, не меньшую
    `(s − a[i], i + 1)`. Если её значение совпадает с нужным, найдена требуемая пара.

Выбор обычных массивов соответствует исходным данным и обеспечивает прямой доступ
к элементам. В задачах 4 и 8 дополнительные массивы нужны для результата переменной
длины, в задаче 12 записи сохраняют исходные индексы после сортировки.
Внешние библиотеки используются только для тестирования и проверок проекта.

## Почему задача 12 выбирает правильную пару

При фиксированном `i` требуется значение `s − a[i]` с индексом не меньше `i + 1`.
Поскольку записи упорядочены по значению и индексу, нижняя граница для такой пары
даёт наименьший допустимый `j`. Если значение найденной записи другое или позиция
равна длине массива, подходящего `j` нет.

Первый индекс перебирается слева направо. Значит, первая успешная попытка имеет
минимальный `i`, а двоичный поиск уже выбрал минимальный `j` для этого `i`.
Проверка `j ≥ i + 1` не позволяет использовать один элемент дважды.
Входной массив остаётся неизменным.

## Ручные тесты

Каждый ввод в таблице содержит `n`, элементы массива и, если нужен, дополнительный параметр.
Вместо пробелов можно использовать переводы строк. Символ `↵` обозначает перевод строки.

| № | Ввод | Ответ | Что проверяется |
|---|---|---|---|
| 1 | `5 3 -1 9 0 4` | `-1 9` | Минимум и максимум внутри массива |
| 2 | `5 3 8 3 8 2 3` | `0` | Выбор первого из нескольких совпадений |
| 3 | `5 1 2 1 3 1 1` | `3` | Повторяющиеся значения |
| 4 | `5 2 7 2 3 2 2` | `0 2 4` | Порядок индексов |
| 5 | `5 1 100 2 100 3` | `6` | Чётные индексы, а не чётные значения |
| 6 | `5 1 2 3 4 5` | `2` | Значение, равное среднему, не считается |
| 7 | `4 -8 -3 -5 -10` | `-5` | Полностью отрицательный массив |
| 8 | `7 0 -2 4 -1 0 3 -7` | `4 3 ↵ -2 -1 -7` | Исключение нулей и сохранение порядка |
| 9 | `5 -2 -2 0 3 3` | `YES` | Равные соседи допустимы |
| 10 | `4 -6 5 0 7 -3` | `2` | Отрицательный делитель и ноль |
| 11 | `2 1 0` | `1` | Дробное среднее и выбор первого при равенстве |
| 12 | `4 1 2 3 4 5` | `0 3` | Минимизация первого индекса раньше второго |

Дополнительные важные случаи:

- В задаче 4 отсутствие совпадений даёт пустую строку.
- В задаче 8 массив из одних нулей даёт две пустые строки.
- В задаче 5 ввод `3 2147483647 0 2147483647` даёт `4294967294`, что не помещается в `int`.
- В задаче 12 ввод `2 3 3 6` даёт `0 1`, а `3 1 2 4 8` даёт `-1 -1`:
  один элемент `4` нельзя использовать дважды.

## Автоматические проверки

Каждая задача проверяется через настоящий `main` с подменой стандартных потоков
и точным сравнением ответа. После проверки потоки восстанавливаются в `finally`.
Тесты не используют общее изменяемое статическое состояние; запуск последовательный.

Дополнительно проверяются размеры 2 и 99999, крайние значения `int`, отсутствие
совпадений, повторы, отрицательные числа, пустые группы фильтрации и неверный размер ввода.
Для задачи 12 используется независимый полный перебор на 1000 небольших случайных
массивах с фиксированным seed; сравниваются оба индекса и неизменность входного массива.
Нагрузочные тесты включают большие массивы без подходящей пары, с одинаковыми
элементами и с единственной парой в конце.

Расчёты времени и памяти вынесены отдельно в `complexity.md`.
Результаты фактического запуска приведены в `verification.md`.
